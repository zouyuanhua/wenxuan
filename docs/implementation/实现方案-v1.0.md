## 1. 概述

本文档描述问玄 P0 版本的**实际技术实现**:模块划分、关键算法、数据契约、安全设计与部署方式。与早期规划方案的差异如实标注(见 §9 技术债)。

**实现原则(贯穿全部模块)**:

1. **代码算,AI 讲**:一切术数计算(钱象分类/卦名/变卦)由确定性代码完成;LLM 仅基于服务端注入的典籍原文做叙事,禁止自行计算或改写卦象。
2. **不信任前端**:客户端只提交铜钱面(`back`/`front`),卦象由服务端重算。
3. **优雅降级**:典籍库缺失、提示词损坏、上游超时均不崩溃,返回友好错误。

## 3. 模块设计

### 3.1 摇卦与卦象规则 —— `src/hexagram.py`

**职责**:钱象分类、64 卦查名、变卦推导。前端 `js/hexagram.js` 为同源移植(逻辑逐条一致)。

**钱象→爻**(`classify_coins`):

| 三枚钱面 | backCount | 爻 | 阴阳 | 动 |
|---|---|---|---|---|
| 一背二字 | 1 | 少阳 | 阳 | 否 |
| 二背一字 | 2 | 少阴 | 阴 | 否 |
| 三背 | 3 | 老阳 ○ | 阳 | 是(变阴) |
| 三字 | 0 | 老阴 × | 阴 | 是(变阳) |

**卦名查表**(`describe_hexagram`):

```
bits = Σ (1 << i)   # i=0..5,初爻为 bit0;yang=1
BY_BITS[bits] = (卦号, 卦名, 上卦bits, 下卦bits)   # King Wen 卦序 1-64
fullName = 上卦名==下卦名 ? "X为Y" : 上卦象+下卦象+卦名   # 离为火 / 天火同人
symbol  = chr(0x4DC0 + 卦号 - 1)                  # Unicode 卦符
```

**变卦推导**(`change_lines`):仅对 `moving=True` 的爻翻转 yang,其余不变;翻转后再查表得变卦。

**测试锚点**:乾(全阳,7|7<<3)→乾为天;乾初爻动→姤;同人=[7,5]→下离上乾。回归用例见 `tests/test_hexagram.py`。

### 3.2 典籍数据库与防幻觉 —— `src/gua_classics.py`

**数据**:`config/64gua.json`,64 条;`id` 为自下而上阴阳二进制串(101010=既济),与爻数组同构;字段 `gua_ci/tuan_ci/da_xiang/yao_ci[0..6]/xiao_xiang[0..5]`。

**加载**(`load_database`):启动时一次性载入 `GUA_BY_ID`;文件缺失/损坏返回空 dict(全链路优雅降级)。

**典籍依据构建**(`classics_grounding(data)`):

```
id(本卦) = join('1' if line.yang else '0')
id(变卦) = join(翻转动爻后)
块 = [防幻觉指令头]
  + 本卦「名」:卦辞 + 象曰
  + 每个动爻: "{爻位}动爻爻辞：{yao_ci[pos-1]}　小象曰：{xiao_xiang[pos-1]}"
  + 变卦(若与本卦不同): 卦辞 + 象曰
  + 若无动爻: "本卦六爻皆静（无动爻）。"
```

注入位置:`app.interpret()` 中拼接到 system 消息末尾。同时 `classics_summary()` 在响应中返回 `classics`(本卦/变卦卦辞摘要),前端渲染到卦卡供用户核对——**防幻觉对用户可见**。

### 3.3 追问循环 —— `src/followup.py`

无状态设计:前端持有 `history`(此前追问问答),服务端不存储。

`validate_followup(raw)` 规则:

| 规则 | 失败文案 |
|---|---|
| raw 缺失 → None(首次解卦) | — |
| `{}`/非字典/问题空或非字符串 | "追问内容未落笔…" / "追问格式不正确" |
| 问题 > 200 字 | "追问也请精简…" |
| history 条数 ≥ 3 | "此卦已尽，建议心定后另择时再问。" |
| index ≠ len(history)+1 或非 int | "追问次数异常…" |
| history 元素缺 question/answer | "追问记录异常…" |

`app.interpret()` 收到追问时构建多轮 messages:`system(提示词+典籍依据+同卦约束)` → `user(原始卦象 JSON)` → `assistant/user(历史问答)` → `user(【追问n】问题)`,并在 system 追加"偏离卦象范围时礼貌引导回主题"指令。

### 3.4 服务编排 —— `src/app.py`

- **canonicalize(body)**:校验 question(1-2000 字)/lines(6 爻)/followup → 服务端重算 primary/changed/movingLines → 输出统一数据结构(含逐爻 position/coins/name/yang/moving)。
- **interpret()**:构建 payload(system+user/messages)→ `httpx` 流式调用 DeepSeek → 校验 status/finish_reason=stop/长度 ≤20000/密钥不回显 → 返回 `{interpretation, model, hexagram, classics}`。
- **断连取消**(`interpret_until_disconnect`):`asyncio.wait(FIRST_COMPLETED)` 监听 `http.disconnect`,客户端中断即 cancel 上游任务,避免浪费配额。
- **安全**:`SecurityHeadersMiddleware`(CSP/nosniff/referrer/no-store);常量拒绝(JSON `NaN`);请求上限(解卦 32KiB/配置 128KiB);`raw_path` 不解码不落盘(防路径穿越);异常不透出上游诊断。
- **PromptStore**(`prompt_config.py`):提示词运行时读写,临时文件 + 原子替换;损坏/超限 → 503。

### 3.5 前端 —— `src/index.html + js/* + css/*`

- **问事台**(`ask-data.js` 数据驱动):分类宫格/子项签/签语浮入/疏文校验(码点计数 5-200)/入戏提示+抖动/确认 → 焚化转场(1.2s,可跳过)。
- **摇卦**(`app.js` + `hexagram.js`):点击铜钱 → 650ms 翻面动画(`setInterval` 换字/背)→ `castLine()` 落定 → 逐爻记录;六爻齐 → 本卦/变卦卡片(阴阳爻线自绘)。
- **解卦**:POST 后解读以纯文本渲染(模型输出永不作为 HTML);`renderClassics()` 展示卦辞;追问面板维护 `followupsUsed/history`,超限显示收尾文案。
- **音效/震动**:Web Audio 合成 4 种音效(纸签/竹签/轻磬/火焰),`navigator.vibrate` 分级震动;偏好存 localStorage;`prefers-reduced-motion` 全降级。

### 3.6 微信小程序 —— `miniprogram/`

原生四件套;`utils/hexagram.js` 与 Web 同源(差异:随机源为 `Math.random`,每枚仍独立 50/50);`utils/api.js` 封装 `wx.request`(BASE_URL 可配);问事台与摇卦拆为两页,经 `globalData.draft` 传参;音效以 `wx.vibrateShort` 震动替代。

### 3.7 零依赖预览 —— `src/dev_server.py`

stdlib `http.server` 实现:静态服务 + `/api/interpret` 演示(服务端重算 → 64gua.json 实时取引文 → 组装解读,明确标注非真实 AI)。用于无依赖环境的前端验收。

## 4. 关键设计决策记录

| # | 决策 | 理由 |
|---|---|---|
| D-01 | 排盘用代码、LLM 只叙事 | 消除玄学 AI 最大死穴:排盘错误不可验证 |
| D-02 | 典籍原文注入而非依赖模型记忆 | 引文可逐字核对,幻觉可被用户发现 |
| D-03 | 追问无状态(前端持 history) | 服务端零会话存储,P0 最简;与 NFR-01 持久化规划解耦 |
| D-04 | 卦象数据不信任前端 | 安全层校验 + 服务端重算,防伪造 |
| D-05 | 铜钱概率严格 12.5/12.5/37.5/37.5 | 与手工摇钱分布一致,保证"诚心"体验的可信度 |
